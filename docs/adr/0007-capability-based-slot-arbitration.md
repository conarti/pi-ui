# Dynamic capability-based Slot Arbitration for third-party extensions

Hardcoding package names in `extension-superseder` only works for absorbed first-party scripts and replaced prototypes: applying a static blocklist to the wider `pi.dev` ecosystem breaks unknown extensions, whereas Pi's default last-writer-wins registration silently overwrites either `@conarti/pi-ui` surfaces or the user's installed plugins depending on load order. `@conarti/pi-ui` keeps silent superseding strictly for its own absorbed legacy extensions (plus non-prompting visual priority over provider wrappers on core tools) and resolves all third-party contention dynamically by capability (`footer`, `header`, `editor`, `workingIndicator`, colliding `/commands`, `shortcuts`, and custom message/tool renderers): new collisions surface once in a batched `Slot Arbitration` `Modal Card`, persist the chosen owner per slot in user config, and remain switchable live in `Settings Modal`.
