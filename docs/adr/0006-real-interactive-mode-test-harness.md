# End-to-end UI tests against real InteractiveMode instead of hand-rolled host doubles

Hand-rolled host test doubles (`FakeTui`, `ExtensionHarness`, manual `chatContainer.addChild` / `emit` wiring, direct `component.handleMouse` calls, and `overlayStack` inspection) drifted from Pi's real `InteractiveMode`—most notably omitting the `createInteractiveTuiReference` `Proxy` wrapper around `TuiAltScreen` (`this.ui !== this.renderer`) and `createChatViewport`'s nested document hierarchy—allowing broken `Outline Rail`, `Sticky Prompt`, and mouse-selection `Hover Popup` behavior to pass 100% of tests. All UI and extension integration tests must boot Pi's real `InteractiveMode`, `createAgentSessionRuntime`, and `registerFauxProvider` in memory, substituting only process-edge ports (an in-memory virtual `Terminal`, deterministic faux model streams, isolated temp config/session directories, and an injected clipboard provider) while asserting on parsed terminal screen frames and public session state, enforced mechanically by `scripts/check-standards.mjs`.
