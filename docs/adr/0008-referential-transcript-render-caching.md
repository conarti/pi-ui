# Referential transcript and config render caching across 30 fps animation frames

During active turns, 30 fps glimmer animations (`Working`, `Thinking`) call `tui.requestRender()` every `33 ms`, causing `ScrollView` to invoke `chatContainer.render(width)` across every mounted component in the session. `@earendil-works/pi-tui`'s `renderChildLines` avoids $O(N)$ line-array copying across nesting levels only when both child `Component` references (`child === previous.children[i]`) and their returned `string[]` references (`a === b`) remain referentially identical across frames. Allocating fresh wrapper components (`ToolGroupComponent`, `ResponseMetricsRowComponent`) or cloned `string[]` arrays (`[...lines]`), re-wrapping collapsed thinking prose, re-hydrating cloned `SessionManager.getEntries()` arrays on plain-text user cards, or reading `pi-ui.json` synchronously from disk inside `render()` multiplied per-row work by thousands of historical entries (~`71 ms/frame` on a 3,500-entry session, saturating the `33 ms` frame budget).

Completed transcript components and hooks (`ToolGroupController`, `ResponseMetricsRowComponent`, `UserMessageComponent`, `SkillInvocationMessageComponent`, `Markdown.prototype.render`, `ThinkingBlock`, and `TranscriptTurnIndex`) must memoize both `Component` instances and `string[]` outputs by explicit state, width, theme, and version keys (`getPiUiConfigVersion()`, `PromptChipRegistry.version`), returning the exact cached `string[]` reference on hit without mutating it in place. User configuration (`pi-ui.json`) is cached in memory in `src/shared/pi-ui-config.ts` with once-per-frame `statSync` validation inside `withPiUiConfigRenderPass`, and UI rendering/component modules in `src/` are mechanically forbidden from importing `node:fs` by `scripts/check-standards.mjs`.
